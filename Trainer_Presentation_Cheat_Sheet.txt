---------------------------------------------------------
PART 1: TECHNOLOGIES & TOOLS USED
---------------------------------------------------------

1. Google Gemini AI (google-genai)
   Why we use it: To intelligently parse unstructured resume text and reliably extract structured JSON data without making up fake information (hallucination).

2. FastAPI
   Why we use it: To provide a high-performance web server backend for the Vercel deployment. It's extremely fast and lightweight compared to Django or Flask.

3. Vercel
   Why we use it: A serverless deployment platform. We use it to instantly host our web application frontend and FastAPI backend online for free.

4. GSAP (GreenSock)
   Why we use it: An advanced animation library used in our web frontend. It creates ultra-smooth, premium interactions that standard CSS struggles to achieve.

5. python-dotenv
   Why we use it: To securely load sensitive environment variables (like the GEMINI_API_KEY) from a local '.env' file so the key is never hardcoded into the script.

6. Pydantic
   Why we use it: For strict data validation, ensuring the data sent to our API strictly matches the expected format.

---------------------------------------------------------
PART 2: COMMON TRAINER QUESTIONS & YOUR ANSWERS
---------------------------------------------------------

Q: What libraries and technologies did you use in this project?
A: I used Python for the backend, FastAPI for the web server, Google GenAI for extracting data from the text, and HTML/CSS/JavaScript with GSAP for the frontend animations.

Q: How does the Google GenAI library work here?
A: We use the 'google-genai' SDK. The backend reads the raw resume text and sends it to the Gemini model with a strict prompt demanding a structured JSON response. The model extracts the entities, which we parse into a Python dictionary.

Q: How is the generated portfolio actually created?
A: Once Gemini returns the structured JSON, our Python script reads a base 'template.html' file. We use string replacement (e.g. replacing '{{name}}') to dynamically inject the JSON data into the HTML layout, then save it.

Q: How did you satisfy the rubric's local CLI requirement while building a web app?
A: I separated the web API from the main script. 'main.py' is a pure CLI script that handles local file reading to satisfy the rubric perfectly. For the web deployment, I created a dedicated 'api/index.py' file that Vercel uses to run the FastAPI backend.

Q: How do you prevent the AI from making up fake skills (hallucination)?
A: We strictly configured the AI prompt to act as a data extractor, telling it: "Do NOT invent skills, experience, or dates. If something is missing, leave it empty." We also set a low temperature (0.4) so the model favors exact text rather than creativity.

Q: How do you protect your Gemini API Key?
A: We use a '.env' file locally with 'python-dotenv' so the key isn't hardcoded in the script, and we configured it securely as an Environment Variable in Vercel for the live deployment.

PART 3: GIT COMMANDS CHEAT SHEET
---------------------------------------------------------

1. git add .
   What it does: Stages all modified and new files in the directory so they are ready to be committed to the local repository.

2. git commit -m "message"
   What it does: Saves the staged changes into the local repository's history with a descriptive message explaining the update.

3. git push origin main
   What it does: Uploads the local repository commits to the remote GitHub server, which also triggers automatic deployment on Vercel.

4. git revert <commit_hash>
   What it does: Safely undoes a previous commit by creating a new commit with the opposite changes, preserving the project's history.

5. git status
   What it does: Displays the state of the working directory, showing which files are modified, staged, or untracked.

6. git rm <file>
   What it does: Removes a file from both the working directory and the git repository index.
